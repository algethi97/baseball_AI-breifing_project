파이프라인 A 뉴스 크롤링 ➔ 스마트 정형화 ➔ CSV / SQLite DB 추출

사용자가 키워드와 기간을 입력하여 최대 200건의 기사를 수집하고 파일로 영구 적재하는 흐름

1. 검색 트리거

사용자 키워드('LG 트윈스' 등), 기간(최근 7일) 설정 후 [🔍 수집 시작] 클릭

2. 스마트 분할 크롤링

100건 한계를 극복하기 위해 일자별 분할 순회 후 총 최대 200건을 collected_articles에 적재

3. 고속 트랜잭션 적재

PRAGMA WAL 모드로 단일 커밋 원자적 수행. 4개 정규화 테이블에 1.99ms로 초고속 적재

4. 결과 격리 보관

storage/csv/ 및 storage/db/에 타임스탬프 파일로 자동 분리 저장 완료

파이프라인 B 수집 기사 100% 전수 분석 ➔ AI 보고서 생성 ➔ 챗봇 지식 실시간 동기화

수집된 기사를 LLM이 종합 분석하여 경기 일자를 포함한 리포트를 작성하고, 챗봇 지식 베이스로 실시간 자동 주입

1. [⚡ 맞춤 보고서 작성]

메모리의 collected_articles 전체 기사를 시계열 및 카테고리별로 프롬프트에 집약

2. OpenAI LLM 심층 생성

주요 경기 결과(경기 일자 필수 명시), 핵심 선수 활약상, 향후 관전 포인트를 Markdown으로 생성

3. 화면 렌더링 & 지식 주입

보고서가 화면에 표출되며 챗봇 상단에 🟢 보고서 연동 완료 배너 자동 활성화

4. 선택적 1회 단독 저장

사용자가 [💾 보고서 MD 저장] 클릭 시 storage/report/ 디렉터리에 깔끔하게 1회 저장

파이프라인 C 대화형 챗봇 지식 검색 & 컨텍스트 후속 문답 (Dynamic RAG-like Prompting)

현재 세션의 기사와 보고서를 동적으로 시스템 프롬프트에 병합하여 환각(Hallucination) 없이 정확한 후속 Q&A 수행

1. 사용자 질의 접수

퀵 추천 질문 클릭 또는 직접 질문 입력 ("방금 수집한 기사에서 결승타 친 선수는 누구야?")

2. 동적 컨텍스트 인젝션

System Prompt에 KBO 기본 지식 + 수집 기사 제목/발췌 요약 + 마크다운 보고서 전문을 동적 주입

3. 답변 표출 & 연속 대화

기사와 보고서 내용을 인용하여 정확한 근거 기반 답변 생성. 대화 이력 유지로 문맥 연속성 지원

파이프라인 D 기상청 초단기실황 수집 ➔ 좌표 보정 ➔ 우천 취소 우려 지수 판정

1. 11개 구장 좌표 매핑

잠실, 고척, 문학, 사직 등 11개 구장의 기상청 공식 격자 좌표(nx, ny) 로드

2. 발표시각 자동 보정

매시 40분 데이터 생성 규칙에 따라 현재 분(Minute)이 40분 이전이면 직전 시각으로 자동 롤백

3. 초단기실황 API 호출

공공데이터포털 API 호출을 통해 기온(T1H), 강수량(RN1), 습도(REH), 풍속(WSD) 파싱

4. 우천 지수 매트릭스 판정

고척돔(실내) ➔ 100% 정상 진행, 일반 구장 ➔ 강수량/풍속에 따른 5단계 등급 산정

🗄️ 관계형 데이터베이스 정규화 스키마 (설계안 B - 4개 테이블 모델)

SQLite 3.x RDBMS

기사와 수집 세션 간의 다대다(N:M) 관계를 매핑 테이블(article_keywords)로 분리하고, URL 고유 제약조건(UNIQUE)을 부여하여 데이터 중복 적재를 원천 방지한 고도화된 정규화 모델입니다.

⚡

SQLite PRAGMA 엔진 튜닝 (1.99ms 초고속 벌크 적재 기술)

synchronous = OFF;

OS 디스크 플러시 대기를 생략하여 파일 I/O 병목을 90% 이상 제거

journal_mode = WAL;

Write-Ahead Logging으로 동시 읽기/쓰기 잠금 경합을 완전히 배제

cache_size = 10000;

약 40MB의 인메모리 페이지 캐시를 확보하여 디스크 스왑 방지

temp_store = MEMORY;

임시 인덱스 및 정렬 연산을 RAM에서만 전용 처리
